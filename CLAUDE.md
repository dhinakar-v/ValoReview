# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Requires [uv](https://docs.astral.sh/uv/). Runners are `.bat` wrappers that `pushd` to the repo root, forward all arguments and propagate the exit code — they work from any directory.

```
uv sync                                    # create .venv, install project + dev tools
runners\test.bat                           # uv run pytest
runners\test.bat tests/test_vrfview.py     # one file
runners\test.bat tests/test_vrfview.py -k killer_victim   # one test
runners\lint.bat                           # ruff check .   (config: ruff.toml)
runners\format.bat                         # ruff format .
```

Pipeline CLIs: `runners\vrf-reader.bat`, `vrf-to-json.bat`, `vrf-net.bat`, `vrf-view.bat`, `vrf-app.bat`, `vrf-serve.bat`, `make-icons.bat`, `make-theme.bat`, `make-golden.bat`, `fetch-assets.bat` — see README for their subcommands.

```
cd web && npm install && npm run build    # the browser interface
cd web && npm run dev                     # vite, proxying /api to the server
cd web && npm test                        # vitest
```

## Import layout

`libraries/` is the **source root, not a package**. `pyproject.toml` maps its contents onto the install root (`sources = ["libraries"]`), so `import vrf_reader`, `import vrfnet`, `import vrfview` resolve after `uv sync` — never `libraries.vrfnet`. `scripts/` is _not_ installed; pytest reaches it via `pythonpath = ["scripts"]`. Adding a new CLI means a file in `scripts/` plus a runner in `runners/`; adding importable code means `libraries/`. `web/` is the browser interface and is not Python at all; its own `README.md` carries the npm dependency reasoning, the way `pyproject.toml`'s comment block carries the Python one.

Note the deliberate name pairing: `scripts/vrf_net.py` drives `libraries/vrfnet/`, `scripts/vrf_view.py` drives `libraries/vrfview/`, `scripts/vrf_serve.py` drives `libraries/vrfserve/`. They must not sit in the same directory or the package shadows the script on import. The server package is `vrfserve` and not `vrfapi` because `libraries/valapi.py` is already Riot's API client, and the two names side by side in one import block are a reading hazard.

## Architecture

Eight layers, bottom up. The last two are the web interface; the two before them are the CustomTkinter one, which the web interface is replacing:

**Container — `libraries/vrf_reader.py`, `vrf_to_json.py`.** A `.vrf` is a UE local-file replay container with Riot additions: fixed header then `[uint32 type][uint32 size][payload]` chunks of type HEADER / REPLAYDATA / CHECKPOINT / EVENT. Nothing is encrypted. Only REPLAYDATA and CHECKPOINT are Oodle-compressed (Mermaid); everything the viewer and the event timeline need lives in plain chunks, which is why the viewer needs no DLL.

**Decoder — `csharp/VrfPositions/`, reached by `libraries/vrfview/csharpdecode.py`.** The one thing that turns a `.vrf` into positions. It is a small C# program referencing `michel-giehl/ValorantReplayParser` (cloned beside this repo; `runners\build-decoder.bat`, needs the .NET 10 SDK) that emits thinned movement samples and actor spawns as one JSON file. It exists because the identical decode is ~4 s there and ~4 min in `vrfnet` — the cost was never decompression (31 blocks, 47.2 MB → 127.9 MB, about one second) but three million movement records through a Python-int bit reader. **Do not take its decompressor**: `OozSharpOodleDecompressor` wraps OozSharp, a partial Mermaid decoder (no Huffman, no TANS, seven `NotImplementedException` paths) that is slower than the native `oo2core` and carries a GPLv3 header under an MIT package. It emits facts only — which actor is a player, which spawn is an ability, how casts group all stay in Python. See `docs/valorant-replay-parser-features.md`.

**Replication stream — `libraries/vrfnet/`.** No longer in the app's decode path, and kept deliberately: it decodes the same stream independently, in a different language from a different source, and the two agree on all 10,544 samples of the reference 12.10 decode exactly. That is the only check on the decoder above, so do not delete it. Still driven by `runners\vrf-net.bat` for calibration and research. A port of the UE net stack, one module per engine concept, each mirroring a named UE class: `demodriver` (byte-addressed demo frames, `UDemoNetDriver`) → `datachannel` (bit-addressed packets → bunches, `UNetConnection`/`FInBunch`) → `actors` (`UActorChannel`, spawn identity and content-block framing), with `packagemap` (`UPackageMapClient` — NetGUID cache and net field export groups) and `session` (state that persists across blocks: GUID cache, export table, channel table) spanning all of them. `bitreader` is LSB-first and backed by a Python int, so construct one per playback packet (≤2048 bytes), never per decompressed block.

**The property payload is obfuscated, not unparsed.** Riot whitens every content-block payload with a keystream seeded `payload_bits ^ actor_net_guid`; underneath it is stock UE. `payload_transform` undoes it (one class per build, ported from `michel-giehl/ValorantReplayParser`, MIT — see `THIRD_PARTY.md`), `properties` runs the property loop, and `movement` decodes the RPC that carries player positions. **Never add a nearest-version fallback to `payload_transform`** — an unsupported build must raise, or a porting bug becomes indistinguishable from a version mismatch. Only 12.10, 12.11 and 13.00–13.02 have transforms; 11.11 is permanently out of reach, including the canonical `039f3991…` capture.

`clean_packet_rate` is computed from bunch _headers_ and never enters a payload, so it is blind to this layer — it sat at 99.98% while 100% of payloads were undecodable. Score property work with `PropertyStats.rep_layout_rate`, and position work against ground truth: killer and victim within weapon range at every `characterDeath`.

**Names — `libraries/valapi.py`, `valcatalog.py`.** `valapi` is a stdlib client for Riot's official API (`docs/valorant-api.md` is its reference); `valcatalog` reduces a `val-content-v1` response — or the `fetch-assets` manifest, which needs no key — to the only two joins a replay needs: map asset path → name, agent UUID → name. `vrfview/names.py` applies them and nothing else consumes them.

**Viewer — `libraries/vrfview/`.** `loader` converges a `.vrf` and a `vrf_to_json` JSON onto one `Replay` (tests assert the two produce equal models); `tracks` decodes positions and codenames out of the replication stream; `infer` derives everything the file does not state; `names` looks up what is external; `state.state_at(t)` recomputes a snapshot from scratch per frame (no accumulation, so seeking backwards is as correct as playing forward). The UI is CustomTkinter: `app` is the two-page router, `viewer` assembles the viewer page, `panels` draws the two mirrored team columns, `minimap` is the centre canvas (with `MissingArtView` as its no-radar sentence), `controls` holds the timeline strip and the transport bar, `mapref` and `abilitywindow` are the two Toplevels, `images`/`icons`/`theme`/`clock`/`sight`/`abilities` support them. `minimap` and the strip are `tk.Canvas` inside CTk frames, because a themed widget owns its geometry and cannot be drawn into. `pipeline.open_replay` is those four steps in one place -- read, infer, attach whatever was already decoded, name -- and both interfaces call it rather than retyping them; `provenance` is the account of what came from where, as sections rather than a text blob, so a page can lay it out and `viewer.provenance_text` is now a renderer over it. The order is read → decode → infer → name, and it matters: `infer` cross-checks its team split against the codenames, and `names` needs them to name anybody. `model`, `infer`, `state`, `abilities`, `sight`, `provenance`, `positionfile`, `positioncache` and `csharpdecode` import no tkinter _and no vrfnet_ — `tracks` is the only module that reaches the decoder — and must stay runnable headlessly; `tests/test_vrfview.py::TestHeadless` walks their imports to prove it.

**Match list — `libraries/vrfhome/`.** `scan` describes a whole library of `.vrf` files from plain chunks only — map, date, duration, round count, player count, build — caching by `(path, mtime, size)`, and is headless: 4.3 s cold for 101 captures, 0.03 s warm, no Oodle and no display. `cards` is the CustomTkinter page over it. A file that fails to parse becomes a card carrying its error, never a silent omission. Two card facts are load-bearing: the `WIN`/`LOSS` badge the brief demands **cannot be built** (no local player, teams are A/B by inference) so every card shows `scan.RESULT_NOT_IN_FILE`; and `positions_available` is a membership test against `payload_transform.SUPPORTED_BRANCHES`, the decoder's own table, so it cannot drift from what the decode will do. On the reference library that is 21 of 101 captures. `vrfhome/cards.py` still shows the other 80 behind SHOW ALL and still draws the `RESULT_NOT_IN_FILE` badge; **the web interface shows neither** — `/api/library` filters to playable with no request that turns it off, and neither `result` nor `build` reaches a card any more, so what is on the disk beyond the playable set is not stated in the browser at all. The one chip a web card carries is that capture's `vrfhome/prewarm.py` state (QUEUED / PREPARING / READY / FAILED). `scan` and `prewarm` must keep importing no tkinter — `tests/test_vrfhome.py` and `tests/test_prewarm.py` assert it.

**Server — `libraries/vrfserve/`.** The HTTP interface, and it decides nothing: `pipeline` reads, `infer` derives, `names` looks up and `tracks` decodes, and a handler that started deciding things would be a fourth place a claim could come from. Nine routes and no more: a route the browser does not call is deleted rather than kept for a caller that might appear, which is why `/api/jobs`, `/api/maps` and `DELETE /api/replays/{id}` are gone along with `wire.sections` and the `result`/`build`/`counts`/`art` fields that only a removed panel read. `ids` keys every capture by a digest of its resolved path so a **URL never carries one** — an id the scan did not produce resolves to nothing, which closes off traversal structurally rather than by validation. `wire` turns the model into plain dicts and imports no framework, no PIL and no vrfnet, so serialisation is testable without a server; int-keyed dicts become records carrying an `actor_id`, because a JSON object key cannot be an integer. `schema` is the same contract as pydantic models, which is what makes the OpenAPI document — and the browser's types after it — derived rather than written twice; it has already earned that by catching a count being sent where `ScanResult.playable` returns a list. `library` holds the scan and at most two open replays, each behind a lock, and a decode will **replace** an entry rather than mutate it — `Replay` is the one mutable dataclass and three modules annotate it in place, so a request must never see one whose positions have landed but whose codenames have not. Handlers are sync `def`: FastAPI runs those in a threadpool, and an `async def` doing a twelve-megabyte sidecar read would block the loop. `tests/test_vrfserve.py` asserts none of the package reaches a toolkit, which is what will make deleting the CTk modules safe.

**Browser — `web/`.** React over `vrfserve`, Vite-built into `web/dist`, which the server mounts at `/` when it is there and names the command for when it is not. Two build facts are load-bearing and written in both places: the bundle goes to `dist/static/`, **not** Vite's default `dist/assets/`, because the server serves Riot's art at `/assets` and a bundle there would be shadowed by it; and the server serves `index.html` for any unmatched non-API path, because the page routes on the client and `/replay/<id>` is an address no file answers to — but **never for an `/api/` path**, or a withdrawn endpoint answers 200 with a document of HTML and the client reports something unrelated to what went wrong. A map is addressed by its **display name** (`/api/maps/Ascent`), not by `map_url`: `ArtCache.maps` is keyed by `map_url` because that is the exact join a replay states, and `/Game/Maps/Infinity/Infinity` cannot be a URL segment. `web/src/theme.generated.css` is written by `scripts/make_theme.py` from `vrfview/theme.py` and `tests/test_theme.py` fails when it goes stale — the palette carries an argument (the brief's hues, but A and B rather than ATK and DEF, because which side attacked is not recoverable) and generating it keeps the values and the reason together.

**The design system has three owners, and only one of them is Python.** `web/src/tokens.css` is hand-written and holds everything that is not a colour -- space, radius, type scale, elevation, motion, stacking -- because `theme.py` is a palette and Tk geometry is not CSS geometry, so there is no second copy to drift from. `web/src/theme.generated.css` holds every colour and is generated, because the palette carries an argument and the desktop app and both canvases share it. `web/src/fonts.css` holds four bundled `woff2` files: the stacks used to name Tungsten and DIN Next with nothing behind them, so what every machine actually rendered was Impact and Arial. The UI face is **Plus Jakarta Sans** and was Inter, which is a good face and the wrong one to have reached for -- it is the default a decade of interfaces already picked, so a tool set in it reads as unstyled rather than as neutral; the replacement has a taller x-height, which is what keeps the 11px and 12px labels this interface is full of legible, and is 27KB against 48KB. `MinimapCanvas.LABEL_FONT` repeats that stack as a string and is the one duplication this interface cannot design away, because a canvas cannot inherit a font and the 2D canvas is what the Playwright suite photographs -- change one, change the other. They are bundled rather than linked because this page is served by a local process against files on a disk and has to work with no network. The surfaces are a **ramp** rather than the brief's five flat greys -- a panel raised above a page, a row hovered inside it, an input sunk below it and a divider stronger than a hairline were all one value, which is why the old page read flat -- and `--team-a`/`--team-b` are **unchanged and pixel-tested**: `minimap.spec.ts` counts a marker within 36 RGB of a team colour, `scene.spec.ts` identifies one by hue after 3D lighting, so moving either toward grey or toward the other fails both.

**The ramp fixed the fills and the edges stayed flat, which is what `--bezel` is for.** Every enclosure was one `1px solid var(--border)` -- seventeen of them, identical -- so nothing was ever *above* anything, and `--shadow-2`/`--shadow-3` sat declared and unused. A bezel is four stacked `box-shadow` rings and an inset highlight: a hairline, a lighter tray standing the core off the page, the tray's own edge, then the drop. It is **not** a wrapper element, and does not need to be -- an outer shadow's corner radius is `border-radius + spread`, so the rings are concentric for free and `--radius-tray` minus `--ring` is `--radius-core` by construction. That is what kept the whole treatment inside the stylesheet. Two consequences are load-bearing and neither is obvious: a shadow occupies **no layout space**, so every gap between bezelled elements carries `--ring` twice or the trays overlap, and `.page-body` pads by `--ring` with a matching negative margin because setting `overflow-y` computes `overflow-x` to `auto` and the trays would otherwise raise a horizontal scrollbar on a column with nothing to scroll. The **one** bezel built from two elements is `.panel.stage.tray` > `.stage-core`, and the reason is a test: `gallery.spec.ts` calls `stage.screenshot()`, Playwright captures a bounding box, and a bounding box excludes box-shadow -- so the committed gallery images would show a core with its tray sliced off. The five empty-state panels carry no `.tray` and keep the shadow bezel.

**The map has a team down each side, and that is the desktop viewer's layout rather than a new one.** `vrfview/panels.py` draws two mirrored team columns flanking the centre canvas; the first web port kept the idea and lost the placement, stacking both under a square map that is bounded by viewport *height* -- so about a third of a wide window was empty either side of the only object worth looking at, while the names belonging to those markers sat below the fold. `.viewer-grid` puts them back. The map does not get smaller: it was already height-bound, so the gutters are reclaimed space rather than borrowed. Narrow is the base case and is a column with the map first (`order: -1`); the flanking layout switches on at 1100px, which is the stage's 320px floor plus two 240px gutters plus the gaps rather than a round number. A is left and B is right **purely by label** -- `infer` two-colours a graph and does not decide who attacked -- so nothing may sort by score, and a player it could not colour goes in a row-spanning `.gutter.span`, never a third column. Where a capture has no positions the stage is a sentence in a short panel, and the roster goes back to being a panel of its own: columns flanking a paragraph would be a layout pretending there is something to look at.

**An icon sits beside a label and never instead of it, and that is a test constraint rather than a preference.** There is not one `data-testid` in this repository: every DOM assertion is text, ARIA role-name, class or `title`, so `2D`, `3D`, `UTILITY`, `TRAILS`, `SIGHT`, `CALLOUTS`, `DECODE POSITIONS`, `title="Next event"`, `title="Back to the start"`, `a.card`, `canvas.minimap`, `.clock-readout`, `.stage-canvas` and `.panel.stage` are an interface other files depend on. `views/icons.tsx` therefore sets `aria-hidden` and `focusable={false}` centrally rather than at each call site, and `views/ui.tsx` takes `label` as a **string** so no caller can split one across nodes -- `findByText` matches an element's direct text children, and a label concatenated with anything else stops being found. `views/ui.test.tsx` is the standing check. The wordmark and favicon are inline `<svg>` and a file, never an `<img>`, because `MatchList.test.tsx` asserts there is no `<img>` anywhere on the page in the no-thumbnail state.

**Where a role is claimed, the behaviour it promises is implemented — that is what the last accessibility pass was about, and every item was a real defect rather than a policy.** Four are worth knowing before touching a control. A `<label>` names the control it wraps by its **text content**, so `ui.Field`'s `aria-label` named the label element and left the match list's map filter an anonymous combo box; the name is now an `.sr-only` span, clipped to 1px rather than `display: none` or `visibility: hidden`, both of which take an element back _out_ of the accessibility tree. `role="tablist"` is a contract and not a label — a reader that sees it tells the user to arrow between the tabs and looks for the panel each one controls — so `ui.Tabs` now has a roving `tabIndex`, arrow keys with Home/End, and `aria-controls` pointing at a `ui.TabPanel` that names the tab back; the two ids are derived from the tab's own id because the strip and its panel are rendered by different components and a `useId` cannot cross that boundary. The skip link in `AppFrame` targets a `<main>` carrying `tabIndex={-1}`, because a link that moves only the _scroll_ leaves the focus in the bar and the next Tab returns to what it was meant to skip. And `color-scheme: dark` is in `app.css` and not in the generated palette: it is not a colour, it names which of the browser's own two themes paints the scrollbars and the `<select>` popup. `views/ui.test.tsx` is the standing check on the first two, which are the two that regress silently.

**The interface has a voice, and it is off until somebody asks for it.** `web/src/views/sound.ts` synthesises six short voices from oscillators and gain envelopes -- no audio files, no dependency, nothing whose licence would need tracking the way the fonts' does. Three properties are pinned by `sound.test.ts` and each exists for a reason: it is **off by default** (an analytics tool that beeps unasked is a defect report) and remembered in `localStorage`; the `AudioContext` is built on the **first sound played while enabled, never at import**, which is why no page test needs a WebAudio mock under jsdom; and `prefers-reduced-motion` wins over the toggle, the same query the stylesheet reads to zero its transitions. Its store is its own and deliberately not a field on `usePlayback`, which `MapStage.test.tsx` writes to directly. `views/shortcuts.ts` binds the transport keys by calling the same functions the buttons call -- a key that seeked by its own arithmetic would drift from `Replay.event_times` -- and two corrections to that are pinned by `shortcuts.test.tsx`. The listener is on the **window**, so a widget's `preventDefault` does not stop it and `ownsKey` asks the focused element first: Space belongs to a focused `<button>` and the arrow keys with Home/End belong to a `role="tablist"`, both of which this page has. And a key **exists exactly where its control does** -- `useTransportKeys` takes the same two booleans that decide whether SIGHT and CALLOUTS are drawn, because the store is module-level and an `S` that did nothing visible still left the layer on for the next replay opened in that session.

**The playback model runs in the browser, and `tests/golden/` is what keeps the two copies honest.** `state_at` is 0.127 ms on a 199k-sample replay and a round trip is not, so the clock, the track lookup, the snapshot, the transform and the sight cone are ported to `web/src/model/`. `scripts/make_golden.py` builds one synthetic `Replay` and writes what every branch of the Python model produces for it; `tests/test_golden.py` asserts Python still reproduces those files **byte for byte** and `web/src/model/__tests__/parity.test.ts` asserts TypeScript computes the **same values**. A Python change that would break the browser therefore fails in Python's own CI first. Exact equality, never a tolerance — three corrections were needed to earn it and each is written where it lives: `((a % n) + n) % n` rounds twice where CPython's `float_rem` rounds once (`9.8` comes back as `9.800000000000011`); `math.radians` multiplies by a stored `pi / 180` and `(x * Math.PI) / 180` does not; and `hypot` is _approximate by specification_ in both languages, so `sight.forward_uv` uses `sqrt`. The single exception is `atan2`/`cos`/`sin`, which are approximate in both — so `sight.ray_directions` is written into `cone.json` beside each polygon, the far end compares directions within a bound and then marches Python's own directions through arithmetic that is exact.

## Conventions that matter here

**Positions exist for supported builds, and nowhere else.** `vrfview/tracks.py` is the only bridge from the decoder into the model: it decodes movement into `Replay.positions` (per-actor `Track`s, thinned to 10 Hz), reads each pawn's agent codename off its archetype path, and collects the ability actors (below). It needs the built decoder and about four seconds on a full match, and it _never raises for want of positions_ — an unsupported build, an unbuilt decoder or a JSON dump all end as a sentence in `Replay.position_source`. So every consumer must handle both cases: `viewer._make_view` returns a `MinimapView` when the replay has positions _and_ the art cache holds a radar image, and a `MissingArtView` — a **sentence**, never a drawing — otherwise. There is no schematic any more: a diagram in the place a map goes reads as a map however it is captioned, so the two things that can be absent (the decode, the radar image) each get their own sentence instead. Never let a missing track become a plausible coordinate — `MinimapView` draws nothing for an actor whose `Track.at` refused.

**A decode happens once per capture, ever.** `tracks.attach` tries three sources in order: a sidecar beside the file (what `vrf-to-json --positions` writes), then `vrfview/positioncache.py` (`.cache/positions/` under the project root, the convention `libraries/vrfcache.py` now sets for everything disposable), then a real decode, whose result it caches. The complaint against `scan`'s old `out/` was never that it was inside the tree — it was that `Path("out")` is a bare _relative_ path, so running from another directory silently addressed a different cache. `vrfcache` searches upward for `pyproject.toml`, so every entry point resolves one directory whatever the CWD is, and a user can find and delete it. There is no fallback: with no project root above the code (an installed wheel) `vrfcache.root()` raises and each cache degrades to "no entry", because every one of them is an optimisation whose absence costs time and nothing else. `attach_stored` is the same thing with `decode=False`, and `app.open_replay` calls it so a prepared capture opens on the map instead of on a button. `vrfhome/prewarm.py` fills that cache in the background from the match list — one worker, one capture at a time, paused while a viewer is open, stopping between captures, which is now cheap because a capture is seconds rather than minutes. It imports no tkinter, and a status change is marshalled onto Tk with `after` by `app._prepared`, which treats a dead window as a reason to stop rather than an error. The viewer's DECODE POSITIONS button remains for anything not yet prepared; after a decode it re-runs `names.resolve` and rebuilds the body _and_ the transport bar, because the codenames and the casts only exist once the stream has been read.

**Ability casts are inferred from the actors they spawn, and the limits are measured.** There is no ability event in a `.vrf` — `docs/039f3991_summary.md` §6 lists all seven groups, and only `characterUltimateUsed` touches an ability. `vrfview/abilities.py` parses the archetype paths instead: `/Game/Characters/<Codename>/S0/Ability_<SLOT>/<Kind>_...` gives the agent, the keybind (**`Ability_4` is C**) and the kind. Four things were settled by decoding a real capture, not by guessing, and each is written down where it is relied on: only `Pawn_` actors ever move, so **projectile arcs are not decodable**; a cast opens several channels in several places, so which one says where it _ended up_ is a rule (`abilities.PLACING_KINDS`) and not an ordering accident; the `Ability_` actor is not reliably respawned per use, so the pawn names the cast; and a millisecond carrying three or more _distinct agents_ is the engine re-replicating the world, not thirty-three simultaneous decisions. Ability **range is never published** — not in the replay, not in val-content-v1, not in the manifest — so the only figure shown is the measured path length of a pawn's own track. Names join for X and C only; `Ability1`/`Ability2` are Q and E in an order that varies by agent, so those show the internal name read from the path and `art.AgentArt.ability` refuses rather than guessing.

**A smoke has a coordinate, and that is a measurement rather than a decode that was always there.** `csharp/VrfPositions` reads each channel's own `ActorSpawned` transform and `csharpdecode` has parsed it into `Decoded.spawn_locations` since it was written — and nothing consumed it, because nothing had established that those numbers were coordinates rather than plausible noise. The check that settled it uses only data already in hand: **a player's first decoded position is ground truth for where they spawned**, and across the 21 playable captures every one of 210 player pawns has a spawn location within 100 uu of its own first movement sample, a median of 0.0 and a maximum of 91.7. Every one of 18,946 ability actors has one, and 98% to 100% of each kind lands inside the radar image's playable silhouette, where a random coordinate would land inside about a third of the time. `Actor_` is the exception — 13 across the library, tens of thousands of units off the map — so `AbilityCast.landed` refuses a kind `PLACING_KINDS` does not name rather than ranking it last. What is still not decodable is the **path**: only `Pawn_` actors emit movement, so a projectile has a start and an end and nothing in between, and no consumer may draw a curve. `tests/test_movement.py::SpawnLocationsAreRealCoordinates` is the standing check.

**An out-of-play actor is parked about 50,000 uu below the map, and a raw minimum is not a floor.** The stream writes a holding coordinate — x out near -50,000, z about -49,915 — for an actor that is not in play, and 4 of the 21 playable captures carry between 182 and 684 such samples, 0.10% to 0.33% of their totals. `web/src/model/replay.ts:floorZ` is the 3D scene's ground reference and took the minimum, so on those four captures **every marker was lifted three and a half map-widths out of frame and the scene drew no players at all** while the ground rendered perfectly underneath — a quiet map rather than a visible fault, which is why nine months of screenshots would not have caught it. It now measures from the capture's own median and ignores anything more than `OFF_WORLD_DROP_UU` below it: the deepest sample a player legitimately reaches anywhere in the library is 1,025.7 uu below its median, so the threshold is a gap between two populations two orders of magnitude apart rather than a tuned number. **Nothing is dropped from the model** — a parked sample is still in the track, and what a trail should do when it crosses one is an open question about the decode, not about a camera.

**Positive pitch is looking up, and nothing in the file says so.** `Position.pitch` was decoded from the first and rendered by nothing, because no source — the replay, val-content-v1, the manifest — states which half of 0..360 means up, and drawing a view direction on an assumed sign is exactly the plausible wrong answer this codebase refuses. It is measured the way the coordinates are: at every kill the killer's pitch is compared with the true angle to the victim, whose z is also known. Over the whole library that is 2,949 kills at a median error of 0.91° and 98.4% inside 10°, against yaw's 98.7%, and the negated reading is four times worse. The 3D scene renders it; the minimap stays yaw-only, because a top-down projection has nowhere to put the other half. The same measurement caught a real bug: `Track.at` interpolated pitch _linearly_ while interpolating yaw as an angle, so a player crossing the horizon between two samples landed at 180° — pointing backwards — and the 99th-percentile error was 159° rather than 11.4°. **Both angles go through `_lerp_angle`.**

**The sidecar stores facts, not readings.** `positionfile` keeps the raw ability spawns — actor id, archetype path, millisecond, and since version 3 the coordinate the channel opened at — and `tracks._apply_sidecar` regroups them into casts on every load. That is why the grouping rules above could be corrected twice without invalidating a single cached decode. Version 2 added the spawns and version 3 their coordinates; v1 and v2 files still read, and simply have less. A spawn whose transform is unknown is stored as two fields rather than five, never as three zeros: defaulting it would put every such actor on the map's origin.

**A lookup fills in one field with `dataclasses.replace`, never by rebuilding the record.** `names.resolve` listed an `AbilityCast`'s fields by hand to set `agent`, and when a cast learnt where it landed the coordinates were decoded, cached, read back — and silently dropped on the way past. Nothing failed; the casts simply had no placements, which looks exactly like a decode that never found any. `tests/test_abilities.py::TestNamingKeepsEveryOtherField` pins it, and `tracks._name_pawns` was changed the same way for the same reason.

**Line of sight is an approximation of a silhouette, and says so.** There is no collision, navmesh or height data anywhere in this project. `vrfview/sight.py` raycasts the radar PNG's own alpha channel — 57–72% of every published `minimap.png` is fully transparent void — which is measured data about the map rather than an invention, and nothing more. It is off by default, drawn for one selected player, and the caption states in words that it is the radar silhouette, not collision, and 2D only. Directions go through `sight.forward_uv`, which probes a world point and transforms it; trigonometry in uv space puts every cone ninety degrees out, which looks entirely plausible on screen. `SightMap.blocked` uses `math.floor`, not `int` — `int` truncates toward zero, so a ray leaving the left edge would reappear in column 0. **The mask is thresholded in Python and the caption travels with it**: `GET /api/maps/{key}/sight` sends the 256×256 bitmask, `sight.CAPTION` and the constants that produced it in one document, so a browser cannot draw a wedge without having been handed the sentence saying what it is a wedge of — and a browser downscale is not Pillow's, so rebuilding the mask at the far end would make exact parity untestable. A map with no radar on disk is a 404 there, never an empty mask: the layer is _unavailable_, where an empty mask would have every cone silently collapse to nothing.

**A trail never draws a line the position lookup would not.** `Track.at` refuses to interpolate across a gap longer than `MAX_INTERPOLATE_MS` precisely because the straight line would cross whatever is between the two points — and `minimap._draw_pawn_trail` then joined every sample in its window regardless. That inconsistency is fixed in both ports: `web/src/model/track.ts:segments` splits a trail at the same gap, and the 2D and 3D trails both go through it. Player trails are a **new** layer rather than a port (the desktop minimap drew them for ability pawns only) and are off by default.

The one thing drawn at real map coordinates _without_ positions is the **map reference window** (`vrfview/mapref.py`, the _Map_ button): Riot's own callouts, from the `assets/manifest.json` transforms, via `vrfview/art.py`. It is safe because it describes the map and not the match — it is the same picture for every replay on Bind — and it is structurally unable to do otherwise, because `mapref.show` is handed no `Replay`. Keep it that way: positions belong on the minimap, not smuggled in here. It is **desktop-only**: the browser's equivalent page and its `/map/:key` route are gone, and `GET /api/maps/{key}` survives only because `MapStage` reads its radar URL, transform and callouts.

**Art is a picture, never a claim.** `vrfview/art.py` is a second reader over `assets/manifest.json` — `valcatalog` takes names from it, `art` takes file paths, the transform and the callouts. Art resolution is deliberately not part of the model: it never touches `Replay`, has its own `ART CACHE` block in the provenance panel, and a missing or partial `assets/` costs thumbnails, portraits and the minimap image and changes nothing the viewer states (`--no-art` forces that path). Read every PNG path out of the manifest's `files` dict — never build one from a display name, or `KAY/O` breaks. Sizing is Pillow's since Phase 6: `images.ImageCache` resamples to any size and masks a portrait to a circle, and it hands a `PhotoImage` to a canvas but a `CTkImage` to a widget — the two are not interchangeable. `art.png_size`/`art.subsample_for` are gone; they only existed to pick an integer factor for Tk's `subsample`. Transport glyphs come from `scripts/make_icons.py` via `vrfview/icons.py`, which lists the names and the text each control falls back to when `assets/icons/` has not been generated.

**Names are looked up, never invented, and the lookup is offline by default.** Map and agent names are external knowledge, so they live in `vrfview/names.py` rather than `infer`, and they append to `Replay.catalog_notes` rather than `Replay.notes` — a looked-up fact and a derived one are different claims. The search order is `--catalog` → `assets/content-<locale>.json` → `assets/manifest.json` → the built-in table (`loader.MAP_NAMES` for maps, `names.AGENT_CODENAMES` for agents), and whichever answered is always reported. Only `vrf-view.bat catalog --refresh` opens a socket: no command needs `RIOT_API` to view or dump a replay.

There are three joins, and the third has a caveat: map asset path → name, agent UUID → name, and **codename → name** (`Hunter` → Sova) via `developerName`, which only valorant-api.com publishes, so only a `fetch-assets` manifest carries it. The **loadout roster is still not attributable to actor net IDs** — nothing links a loadout slot to an actor and nothing decoded since has changed that. What changed is that a player no longer needs the roster: its pawn states its own archetype, so `Player.codename` is _read_ and `Player.agent` is _looked up_, while `Loadout.agent` still comes from a UUID. The two are never filled from each other; when both resolve, `names` notes that they agree. `val-match-v1` (player names, ranks, economy, positions) is 403 without a production key, so it is implemented and diagnosed but never depended on.

**Read vs. inferred is never blurred.** `loader` fills in only what the file states; `infer` derives teams (bipartite two-colouring of the kill graph), round outcomes, sides and reconnect merges, appends a line to `Replay.notes` for each derivation, and leaves an explicit unknown where it cannot decide. The UI surfaces those notes. Keep new derivations in `infer` and keep them noted.

**`characterDeath` args: `args[1]` is the killer, `args[2]` the victim.** The summary doc originally had this reversed; the symptom is not a crash but players dying twice in a round. `test_killer_victim_order_is_not_reversed` pins it.

**`clean_packet_rate` is the _bunch layer's_ health metric.** Bit-level desync does not degrade gracefully, so anything below ~99% means a layout is wrong, not that the data is noisy. It doubles as the calibration score. It says nothing about anything inside a payload — see the replication-stream section above.

**Version gates are calibrated, not guessed.** The `EEngineNetworkVersionHistory` thresholds for `++Ares-Core+release-11.11` are not public, so `vrfnet/versions.Features` is a plain policy object and `vrfnet/calibrate.py` sweeps every candidate against real packets, scoring by how many bunch loops consume to exactly zero leftover bits. The answer is committed at `libraries/vrfnet/calibrated.json`. Never hard-code a gate; re-run `vrf-net.bat calibrate ... --save` with a few thousand packets (small samples report INCONCLUSIVE even when the winner is right).

**Oodle is no longer on the positions path** — the decoder does its own decompression — but `--decode`, `vrf-to-json` and `vrf-net` still read compressed chunks directly. **Oodle is never vendored.** `libraries/oodlefind.py` resolves `oo2core_*_win64.dll` in order: `--oodle-dll` → `VRF_OODLE_DLL` (real env, then nearest `.env` via `libraries/envfile.py`) → `vendor/` → cache (`.cache/oodle.json`, so once per checkout rather than once per machine — the answer is only meaningful while this tree's `vendor/` and `.env` say what they currently say) → Steam/Epic library scan. The first two are configured deliberately, so a nonexistent path raises rather than falling through to a scan. Valorant itself cannot supply one (statically linked, exports no Oodle symbols).

**Four runtime dependencies, a declined fifth, and one external binary.** The decoding side (`vrf_reader`, `vrf_to_json`, `vrfnet`, `valapi`, `csharpdecode`) is stdlib-only and stays that way — `csharpdecode` shells out with `subprocess` and reads JSON, adding no package. What it shells out _to_ is a compiled C# program built from `csharp/`, which is a real new prerequisite for positions and is why `runnersuild-decoder.bat` and a `vendor/parser/` drop-in both exist. The interfaces on top are not stdlib. `customtkinter` is the desktop widget set the brief specifies and goes when the desktop app does; `Pillow` stays after it, because `sight.SightMap` reads the radar PNG's alpha channel and `make_icons` draws the glyphs. `fastapi` and `uvicorn` are the web interface: `http.server` genuinely lacks routing, streaming responses, request validation and more than one thread, so honouring the rule below meant adding them rather than hand-rolling an ASGI stack. `pydantic` and `starlette` arrive with them, and pydantic is what makes the OpenAPI schema -- and the browser's types -- a derived artefact. Dev group is pytest + ruff + httpx2 (the in-process test client). `pyproject.toml` is the **only** dependency list: there is no `requirements.txt` mirroring it, because a second list drifts from the first and `pip install .` reads the real one. **`python-dotenv` was deliberately not adopted**: `envfile.py` already implements the same contract -- real environment first, nearest `.env` second, no `os.environ` mutation -- so `vrfconfig.py` calls it rather than putting two readers of one `.env` in one process. Add a dependency only when the standard library genuinely lacks the thing.

**Configuration is one key, and it reports where it came from.** `libraries/vrfconfig.py` resolves `DEMO_PATH` (the directory the match list scans) through `envfile`, defaulting to `Demos/`, and returns a `DemoRoot` carrying the provenance sentence alongside the path. A `DEMO_PATH` that does not exist resolves normally and reports `exists = False` -- an empty library is the match list's empty state, not a startup error.

**Everything regenerable lives in one directory, and it is found, not assumed.** `libraries/vrfcache.py` resolves `<project root>/.cache/` by walking up for `pyproject.toml` via `envfile.find_upwards` — the same way `oodlefind.vendor_dir()` finds `vendor/`. Four things live there and nothing else does: `positions/` (decoded sidecars), `oodle.json` (the resolved DLL path), `match-scan.json` (the match list) and `decode/` (the C# decoder's scratch, unlinked the moment it is read). `root()` **raises** rather than falling back — a CWD fallback would recreate the `out/` bug and a `%LOCALAPPDATA%` fallback would recreate the directory this retires — so every caller catches `NoProjectRootError` and degrades to doing the work again. `csharpdecode._scratch_for` is the one exception, keeping a `tempfile` fallback, because a decode must not fail for want of somewhere to put a file it is about to delete. Deleting `.cache/` is a complete reset.

**Positions travel beside a JSON dump, never inside it.** `vrf-to-json ... --positions` decodes tracks once, on the machine that has the decoder built, and writes `<out>.positions.json` (`libraries/vrfview/positionfile.py`); `tracks.attach` reads that sidecar when it is handed a `.json`, so the JSON path stays decoder-free without weakening the test that asserts the two input paths build equal `Replay`s -- `loader.load` still reads only what the container states. A sidecar whose `match_id` disagrees with the replay's is refused with a sentence, because a track drawn for the wrong match looks entirely plausible.

## Tests

`unittest`-style classes run under pytest. Everything runs headlessly with no `.vrf`, no display and no network: `Demos/`, `out/`, `assets/` and `.cache/` are gitignored, so tests needing the reference capture (`Demos/039f3991-5472-4119-bed2-838da0935f60.vrf`) are `skipUnless(...exists())`. Network and DLL-loading tests use small inline fixtures. **`tests/golden/` is committed** — unlike `Demos/`, `out/`, `assets/` and `.cache/` — because it is synthetic, needs no `.vrf` and is the contract two languages are compared against; `runners\make-golden.bat --check` fails when it goes stale, and `tests/test_golden.py` runs the same check.

Ruff runs with nearly every rule family enabled (see `ruff.toml`); test files get a per-file exemption list. Expect lint feedback on error-message style, pathlib usage, boolean traps and complexity.

**The browser has two test tiers, because jsdom cannot see a drawing.** `cd web && npm test` is vitest under jsdom — the model ports against `tests/golden/`, and `MapStage.test.tsx` against every sentence the page says — and needs no server, no `.vrf` and no `assets/`. `npm run test:e2e` is Playwright (`web/e2e/`) against a real Chromium, starting the Python server and Vite itself, and is about pixels only: that every player the model can place is drawn where it says **and nothing else in a team colour is on the canvas**, that the sight cone covers the polygon `sight.cone` computed and covers it better than the same cone rotated a quarter turn, that scrubbing back across a round boundary is pixel-identical, and that the 3D ground correlates with the 2D minimap at the same uv points (0.90) far better than with any mirrored reading (0.07 / 0.33 / 0.18) — which answers the "is the plane flipped" question the `CALLOUTS` layer exists for by arithmetic rather than by eye. It uses `channel: "chromium"` and not the headless shell, because the shell's WebGL is not the browser's. Two mechanics are load-bearing: **the page decodes its own screenshots** (a WebGL canvas cannot be read with `getImageData`, and `preserveDrawingBuffer` would be a production setting existing only for tests), and **the playhead is stepped, never guessed** — `>>` seeks to the next `Replay.event_times` entry, so N presses land on exactly `event_times[N-1]` and a test can compute where everybody should be and then look there.
